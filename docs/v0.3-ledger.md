Baseline: d84733c3207e2e802f7541d9b431bd7b6a767704, published v0.2.0-rc.1.
Release CI 43144779878 passed all native, GUI, reliability and package gates.

Gap report: core structs allow unchecked host edits; assembler has repeated
linear symbol searches and unbounded diagnostic prefix scans; output files

## Phase 1 — passed locally
Added detached observations, atomic checked CPU register/stack edits,
non-acknowledging reads, atomic host RAM/VRAM patching, explicit input/pause/resume
transitions. Public fields remain for source compatibility; arbitrary struct
mutation is outside the validated API. New regression covers rejected state
edits, denied cross-region patches, read-clear inspection and counter exhaustion.
Linux x86_64, Zig 0.17.1: baseline fmt/build/test/demos/acceptance returned 0.
After API changes, `zig build test --test-timeout 2m --summary all`, default
build and Python CLI acceptance returned 0. All four golden hashes unchanged.
Existing word-write/snapshot atomicity, stack exhaustion, malformed encodings,
independent ALU/control tests remain active. No new guest critical defect was
confirmed; the host API gaps above now have checked alternatives. Raw mutable
fields remain an explicit compatibility escape hatch, not safe deserialization.
Phases 2–10 remain open.

## Phase 2 — passed locally
Indexed symbol tables, iterative constant dependency resolution, indexed source
spans, UTF-8/line/symbol limits, bounded multi-error recovery, rich excerpts and
opt-in JSON diagnostics v2. Existing JSON v1 remains available. Related output
files are preflighted and staged before replacement, ROM last. Filesystem crash
atomicity across several destinations is explicitly not promised.

Confirmed defect: reverse-chain resolution scaled cubically in this workload.
Same Linux host, Zig 0.17.1 Debug, three subprocess samples each: 257/513/1025
symbols had median 0.360759/2.908345/23.471808 seconds before, and
0.009486/0.011534/0.016527 after. Includes process startup. Reproduce with
`python3 scripts/symbol_benchmark.py`; no cross-hardware speed claim.

Regression: 4096-deep constants, cycles, invalid UTF-8, allocation failures,
independent diagnostics, denied/aliased output paths and prior-artifact retention.
Debug tests (64), fmt/build, original CLI acceptance and new developer acceptance
returned 0. ReleaseSafe baseline build plus original/new CLI checks returned 0
before inclusion integration. All golden ROMs unchanged. The host inclusion
loader is introduced here as input preparation infrastructure; its sample and
boundary/source-map acceptance close in Phase 3.

## Phase 3 — passed locally
Added a complete multi-file counter project with constants, entry, input and
rendering routines; one documented assembler command builds it. Host-only loader
tracks canonical boundaries/cycles, caps depth/bytes/file visits and attaches
root-relative source origins to checksum-bound maps. Single-file ROMs unchanged.

`python3 scripts/developer_acceptance.py` returned 0: two independent project
copies produced identical ROM/map bytes; real CPU boot halted with R1=42; map
contains lib/input.asm. Missing/cyclic/out-of-root/absolute includes and duplicate
symbols failed without replacing previous ROM. Original acceptance returned 0.
64/64 native tests passed after integration. No network or general linker added.
Native Windows/macOS project acceptance remains a later CI gate.

## Phase 4 — passed locally
Added exact file:line breakpoints, bounded source-statement `next`, default-PC
source lookup, symbol listing/address operands and trap disassembly/source context.
Existing instruction/frame/reverse/snapshot semantics unchanged. The new scripted
acceptance assembles the real multi-file counter, breaks in an included file,
inspects registers/symbolic RAM, steps forward/reverses, saves/restores and
compares snapshot bytes, then runs to HALT with R1=42. Missing source maps fail
explicitly. `zig build`, fmt, 64/64 tests, original and developer CLI acceptance
returned 0 on Linux x86_64 / Zig 0.17.1. Cross-platform execution pending CI.
